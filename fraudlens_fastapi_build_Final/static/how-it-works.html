How FraudLens works

A structured-plus-text classifier, a two-stage explainability pipeline, and a live verification layer — instead of one opaque Real/Fake label.

The core idea

Most fraud-detection systems treat this as a text-only problem: read the posting, return one label, no explanation. FraudLens treats it differently on both counts. It weighs structured metadata — company logo, profile completeness, salary range — alongside the wording of the description, because scammers can imitate legitimate-sounding language far more easily than they can fabricate a consistent company presence. And instead of one label, it reports two independent scores: Content Risk and Verification Status.

Pipeline stages

01 · MODEL

Classification

Five classical ML algorithms were trained and compared on the EMSCAD dataset (17,880 postings, ~4.8% fraudulent) using TF-IDF text features plus metadata: Naive Bayes, Logistic Regression, SVM, Random Forest, and XGBoost. Class imbalance was handled with SMOTE on the training split only, and models were compared on fraud-class F1-score rather than raw accuracy — a naive "always genuine" classifier would score above 95% accuracy while catching zero fraud. LinearSVC (SVM) won with an F1 of 0.845, narrowly ahead of XGBoost at 0.844.

02 · SHAP

Feature attribution

For each prediction, SHAP's Linear Explainer (the correct variant for a linear-boundary model like LinearSVC) produces a ranked list of which features — TF-IDF text tokens and metadata flags — pushed that specific prediction toward "fraudulent" or "genuine," each with a signed weight.

03 · LLM

Plain-English explanation

Raw SHAP output is a list of feature names and numbers — not usable by a non-technical job seeker. The top SHAP features are passed to an LLM (via LangChain, using Groq's Llama 3.1 8B Instant) with a structured prompt that translates them into a short explanation. Two deliberate prompt choices matter here: raw feature names are translated to human-readable phrases before the LLM sees them, and low-signal common words are filtered out first — both fixes for explanations that otherwise leaked implementation detail or read as noisy.

04 · KEYWORDS

Rule-based scam-keyword layer

An independent scam-keyword scanner runs across categories — payment requests, urgency pressure, vague contact info, unrealistic offers — seeded partly from the SMS Spam Collection dataset and kept current from BBB Scam Tracker. It's deliberately separate from the trained model: postings it flags show a 34.2% real fraud rate against a 4.8% dataset-wide baseline, validating it as an independent signal rather than a duplicate of the classifier.

05 · VERIFICATION

Live company checks

Verification Status is computed separately from Content Risk, combining a company registry check (OpenCorporates), a web-presence check (Tavily, requiring the company name to literally appear in matched results — not just loose keyword overlap), and posting metadata like logo/profile presence.

Why two scores, not one

A single blended Real/Fake label collapses two different kinds of evidence — how the posting reads, and whether the company checks out — into one number a user can't interrogate. Keeping them separate means a posting with clean text but an unverifiable company still gets flagged, and vice versa, with the actual reason visible either way.
